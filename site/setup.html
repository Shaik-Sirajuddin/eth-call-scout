SETUP GUIDE · ABOUT 10 MINUTES

Put your PR review
on autopilot.

Install the scanner, choose which paths to inspect, add two GitHub Actions templates, then open a pull request to see the first review. Secu runs in your repository and uses GitHub’s built-in token.

BEFORE YOU START

A repository with JavaScript or TypeScript

Secu’s current analyzer scans JavaScript and TypeScript source in configured paths. It reports contract calls and JSON-RPC requests as static findings; it does not execute your code or guarantee safety.

  • A GitHub repository with Actions enabled
  • Node.js 24 available in Actions
  • A Rust toolchain in the runner to build the parser
STEP 01

Add the scanner to your repository

Copy the scanner, parser, and package files into your repository. Merge package scripts and dependencies with your existing files instead of replacing your project configuration.

git clone https://github.com/x0rc1ph3r/eth-call-scout.git
# Copy or vendor the scanner source and parser into your project.
# Keep the package scripts and dependencies from the template.
npm ci --ignore-scripts
npm run build:parser

STEP 02

Choose paths and trust terms

Create a root .secu file. Start with a narrow set of source paths. Add protocol contracts, wallet addresses, and trusted functions to match your review scope; add addresses to the blacklist only after reviewing them.

{
  "version": 1,
  "includeDefaults": true,
  "scanPaths": ["src", "contracts"],
  "excludeAddresses": [],
  "excludeProtocolIds": [],
  "blacklistAddresses": [],
  "knownAddresses": [],
  "trustedFunctions": [],
  "highSlippageBps": 500,
  "tokens": [],
  "protocols": [],
  "contracts": []
}

knownAddresses can include wallet addresses. Add protocol, token, and contract mappings in their matching lists. trustedFunctions uses function names as scan hints; the report includes detected signatures where available, but these terms are not runtime enforcement selectors.

Keep terms on the base branch. Secu reads .secu and the analyzer from the pull request’s base revision. A proposed change cannot lower its own risk by editing the rules in that same pull request.
STEP 03

Add the two workflow templates

The scan workflow compares findings from base and proposed source, then uploads a Markdown review artifact. The comment workflow runs after a successful scan and posts that artifact as a pull request review.

Template files to copy
Copy both complete files into .github/workflows/. They are pinned to action commit SHAs. The scan job gets read-only repository access; the separate comment job gets review permission and does not check out proposed code.

STEP 04

Keep permissions small

The scanner only needs read access. The separate comment workflow needs permission to create a pull request review, and it reads the generated artifact rather than checking out or running proposed code.

  • Set workflow default permissions to read-only in repository settings.
  • Keep contents: read on the analysis job.
  • Grant pull-requests: write only to the artifact comment job.
  • Do not put API keys or private credentials in the analyzer job.

STEP 05

Open a pull request and inspect the review

Commit .secu and both workflows to your default branch. Open a pull request that adds or changes a contract call inside one of the configured paths. GitHub Actions will attach a Secu review after analysis completes.

  • Confirm the workflow run uses the expected base revision.
  • Check the Markdown artifact if the review did not post.
  • Review target identity and source context before changing trust terms.
  • Compare outcomes with the example PR reviews.
