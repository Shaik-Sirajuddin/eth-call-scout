The trust boundary

The model never becomes the security system.

The agent can plan, read public chain state, and produce a transaction proposal. It cannot alter policy, certify protocol health, bypass simulation, sign arbitrary messages, or touch the underlying provider.

Defense in depth

Each layer can veto. None can grant alone.

01LOCAL · DETERMINISTIC

Executable rules, not prompt promises.

Strict JSON schemas bind wallet, chain, contract, selector, ABI words, value, gas, fees, expiry, and approvals. Unknown fields and unsupported shapes deny.

defaultAction: "deny"
selector: "0x095ea7b3"
maxApproval: "1000000000"
02LIVE · AUTHENTICATED

Whitelist does not mean healthy.

Independent RPCs verify runtime bytecode, storage, and read-call invariants. Threshold-signed state is checked for freshness, exact target binding, and rollback.

03RUNTIME · QUORUM

Simulate effects, not intent.

Trace-capable nodes must agree on the full call tree, logs, gas, native outflow, asset changes, storage writes, and code effects of the exact transaction.

04BOUNDARY · AUDITED

Expose less wallet, keep more control.

The agent receives a guarded provider—not a signer. Raw signing, typed data, raw transactions, chain mutation, permission changes, and unsupported batches are blocked.

EIP-7702 without blind trust

Persistent delegation gets a higher bar.

7702 is off by default. When explicitly enabled, CallScout recovers the authorization signer, binds wallet, chain, and next nonce, verifies the delegate’s live runtime code hash, rejects delegation chains, and requires the state diff to prove the exact code change.

Simulation catches malicious behavior in this transaction. Code identity protects against behavior that could emerge later under different callers or state.
